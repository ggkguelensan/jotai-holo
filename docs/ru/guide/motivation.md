# Зачем jotai-holo

Модель описывает изменение данных. View описывает их отображение. Связь между ними хочется видеть в одном объявлении, без кастомного хука, который лишь передаёт значения атомов и сеттеры.

## От хуков к привязке

Нативного Jotai уже достаточно:

```tsx
function NameField() {
  const name = useAtomValue($name);
  const change = useSetAtom(changeName);
  return <NameView name={name} onChange={change} title="Display name" />;
}
```

Для небольшого компонента это хороший вариант. Если такое связывание повторяется по всему UI, `holo` позволяет описать его декларативно:

<<< @/../examples/documentation.tsx#holo

Подход полезен для переиспользуемых View в Storybook, тестов с обычными пропсами и подписок рядом с отображающими данные компонентами. Если компонент уже содержит много локальной логики на хуках, выделение View может добавить лишний уровень косвенности.

## Почему state, actions и bindProps разделены?

Один writable atom может давать и значение, и колбэк. Функция может быть пропсом, React-компонентом или действием. Разделы явно задают операцию без распознавания объектов во время выполнения. Один нативный атом можно указать в `state` и `actions` под разными именами пропсов.

`core` обозначает роль компонента в собранной привязке, а `NameView` — его роль в UI. `bindProps` задаёт фиксированные пропсы View. `ctx.props` содержит входные данные для lifecycle-обработчиков.

## Небольшой словарь, нативная семантика

| Задача                        | Инструмент                  | Граница                                            |
| ----------------------------- | --------------------------- | -------------------------------------------------- |
| Значения и производные данные | stateAtom                   | Нативные атомы; сложные перегрузки остаются у atom |
| Команды и факты               | actionAtom / eventAtom      | Явные вызовы без хранения payload события          |
| Объединение и проекции        | ion / prism                 | Зависимости Jotai и Object.is                      |
| Реакция на доменный факт      | bond                        | Явное подключение к конкретному store              |
| Привязка, список, выбор View  | holo / holoList / holoMatch | Обычные пропсы и lifecycle React                   |
| Идентичность модели в scope   | holoMolecule                | Опциональный Bunshi entry, отдельно от ядра        |

Имена используют молекулярную метафору. Holo напоминает о собранном холоферменте, а `Re` в знаке обозначает React. Это образ для айдентики, а не модель химии.

## Аналогии и материалы

[Мотивация Reflect](https://reflect.effector.dev/learn/motivation) — прямой источник идеи объявлять привязки вне компонентов. Holo переносит этот подход на Jotai без рантайма Effector.

[Руководство Jotai по производительности](https://jotai.org/docs/guides/performance) помогает выбрать границы подписок. [Статья React о событиях и эффектах](https://react.dev/learn/separating-events-from-effects) помогает отделить команду от реактивной синхронизации. Holo оставляет этот выбор явным, не вводя универсальную абстракцию эффектов.
