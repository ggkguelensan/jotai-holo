# Рендеринг и async

## Что работает лениво?

Объявление атома или привязки не запускает селектор, не создаёт модель Bunshi и не монтирует View. Работа начинается через чтения и подписки Jotai. `bond.connect(store)` явно активирует триггер; обработчики событий активируются при подписке.

| Операция                                    | Ожидаемая работа                                           |
| ------------------------------------------- | ---------------------------------------------------------- |
| Объявить селекторы prism                    | Ни один не запускается                                     |
| Прочитать один выход prism                  | Вычисляется только он                                      |
| Изменить источник при активной подписке     | Селектор пересчитывается; Object.is определяет уведомление |
| Изменить посторонний атом                   | Эта запись не обновляет привязанный View                   |
| Изменить writable target без state-привязки | У action-only привязки нет подписки на чтение              |
| Передать новый объект-проп от родителя      | Shallow comparison React может вызвать рендер View         |
| Переставить holoList со стабильными ключами | Локальное состояние строк сохраняется; mapping выполняется |

Фиксированное число вызовов компонента не гарантируется: React может делать пробные рендеры и повторять работу в development. Измеряйте отдельно commits, подписки, селекторы и вызовы View. Большой View целиком обновляется при изменении одного связанного пропса; при необходимости связывайте небольшие компоненты.

## Promise в состоянии

`stateAtom`, `ion` и `prism` сохраняют Promise как значение. React-привязки разворачивают его для View. Размещайте асинхронный подключённый компонент внутри `<Suspense>` и error boundary. Чтения запускаются вместе; разрешённый async-атом не создаёт новый Suspense при изменении соседнего синхронного значения.

Для чтений с отменой используйте нативный `atom(async (get, { signal }) => …)` — holo принимает его напрямую. `ion` не ожидает входные Promise автоматически. `prism` не отменяет уже запущенный Promise селектора.

Первый Suspense откладывает commit: **cage.onMount не может инициализировать данные, блокирующие первый рендер**. Инициализируйте их заранее или запускайте загрузку в модели. Обычное последующее скрытие через Suspense не закрывает passive cage; реальный unmount закрывает.

## Асинхронные действия

Действия возвращают исходный результат и Promise. Они не отменяются, не сериализуются и не реализуют rollback или latest-wins. [Пример профиля](/ru/recipes/profile) явно запрещает параллельное сохранение и обрабатывает ошибки в модели. `actionAtom` публикует аргументы после возврата синхронной части, в том числе pending Promise. Для подтверждённого успеха публикуйте отдельный факт после `await`.
