# Выбор инструмента

Используйте самую простую абстракцию, которая выражает задачу. Нативные атомы поддерживаются во всех привязках holo. Таблица сравнивает роли, а не обещает эквивалентность возможностей.

| Задача                          | С чего начать                       | Что добавляет holo                                                      |
| ------------------------------- | ----------------------------------- | ----------------------------------------------------------------------- |
| Локальное состояние компонента  | useAtom / useAtomValue / useSetAtom | Декларация для повторяющегося связывания с View                         |
| Условные производные чтения     | atom(get => …)                      | stateAtom сужает интерфейс, ion задаёт фиксированные источники          |
| Одна проекция со своей equality | selectAtom                          | prism объявляет несколько независимых проекций без custom equality      |
| Writable атомы элементов        | splitAtom                           | holoList отображает View по ключам, не заменяя атомы элементов          |
| Реактивный внешний ресурс       | jotai-effect                        | cage передаёт committed-пропсы в модель, не управляя любыми ресурсами   |
| Вызов или доменный факт         | actionAtom / eventAtom              | bond может реагировать на каждый вызов независимо от равенства значений |
| Кеш серверных данных            | jotai-tanstack-query                | holo принимает его атомы без собственного кеша и retry                  |
| DI и модели в scope             | Bunshi                              | Опциональный адаптер селекторов без новой системы scope                 |

## Почему не atomWithListeners?

Официальный [рецепт atomWithListeners](https://jotai.org/docs/recipes/atom-with-listeners) показывает уведомления вместе с записью состояния и React-хук для подписчиков. Это рецепт для адаптации, а не экспортируемая утилита Jotai. У наших событий другой контракт: payload не хранится, store указан явно, disposer работает вне React, одинаковые payload доставляются повторно, ошибки потребителей обрабатываются отдельно. Для наблюдения за состоянием лучше подходят `store.sub` и `jotai-effect`.

## Почему нет effectAtom?

[Jotai-effect](https://jotai.org/docs/extensions/effect) уже предоставляет `observe`, `atomEffect` и `withAtomEffect`. Переименование этого механизма увеличило бы API без нового поведения. Используйте `observe` для реактивного эффекта на уровне store, `withAtomEffect` для ресурса с жизненным циклом подписки, а `bond` — для маршрутизации явных уведомлений.
