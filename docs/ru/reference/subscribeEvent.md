# subscribeEvent

Подписка на событие вне React. Импорт из корня или vanilla entry. Возвращает функцию освобождения подписки.

## Контракт

`subscribeEvent(store, event, listener, { onError? }) → stop`

- Подписка действует сразу только в указанном store, без replay. Владение независимо; `stop()` идемпотентен.
- Колбэки доставляются синхронно через общую FIFO-очередь. Вложенные уведомления ставятся в очередь; это не персистентная система задач.
- Sync throw и rejection возвращённого Promise передаются в onError этого подписчика; без него логируются. Другие потребители продолжают работу.
- Остальные возвращаемые значения игнорируются. Отписка не отменяет уже начатую async-работу. Rejection после отписки логируется вместо обращения к обработчику закрытого владельца.
- Подписывайтесь при создании приложения/сессии или в React effect, никогда во время render. Освобождайте подписку вместе с владельцем.

## Почему такой API

Нативный store.sub наблюдает изменения значений, а write-only событие с постоянным null так не наблюдается. Разделение создания и подписки сохраняет маленький код публикации и явное владение. Для связей атомов используйте bond, для реактивных эффектов состояния — jotai-effect.

## Аналогии и материалы

- [Jotai atom](https://jotai.org/docs/core/atom) — исходные контракты primitive, read-only и write-only атомов.
- [Jotai effect](https://jotai.org/docs/extensions/effect) — observe — альтернатива для синхронизации по состоянию.
