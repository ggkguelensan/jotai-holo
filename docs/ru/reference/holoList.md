# holoList

Отображает строки со стабильными ключами из атома массива. Импорт из `jotai-holo`.

## Контракт

Обязательны source, core, getKey и mapItem. Поддерживаются state/actions/bindProps/cage из holo и необязательный empty View. Source может содержать Promise; нужны Suspense/error boundary.

mapItem возвращает обычные пропсы строки, а не atom bindings; ключи не должны пересекаться с разделами привязки. Оставшиеся обязательные пропсы строки становятся публичными пропсами списка и передаются empty View. Пустой источник не создаёт строки и подписки их state.

Стабильные уникальные ключи сохраняют идентичность строк при перестановке. Дубли stringified-ключей вызывают ошибку. Новый массив запускает mapping всех строк; shallow-equal пропсы позволяют пропустить рендер View. У каждой строки свои cage и подписки; удаление освобождает их. Общая state-привязка может обновлять все строки.

Нет виртуализации, автоматического создания атомов элементов и автоматической привязки atom-valued результатов mapItem. Для больших списков комбинируйте подходящую модель данных с внешним virtualizer.

## Почему такой API

List-привязка в духе Reflect решает задачу композиции UI. getKey обязателен, чтобы идентичность строк выбиралась явно. Jotai splitAtom решает другую задачу: создаёт атомы элементов с writable-операциями. Если нужна такая модель, используйте splitAtom и явно свяжите её с отображением.

## Аналогии и материалы

- [Jotai splitAtom](https://jotai.org/docs/utilities/split) — производные атомы элементов вместо адаптера рендеринга.
- [Jotai performance](https://jotai.org/docs/guides/performance) — зачем нужны стабильные проекции и небольшие границы подписок.
