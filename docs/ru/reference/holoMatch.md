# holoMatch

Выбирает View по строковому или числовому атому. Импорт из `jotai-holo`.

<<< @/../examples/documentation.tsx#match

## Контракт

`holoMatch({ source, cases, fallback? })`

Для закрытого literal union нужны все cases либо fallback. Открытый string/number требует fallback. Source может содержать Promise; ожидание и ошибки обрабатываются React boundaries. Неизвестный ключ без fallback также вызывает runtime-ошибку.

Монтируется только активная ветка. Смена совпавшего ключа перемонтирует ветку, даже если оба ключа используют один View. Последовательные неизвестные ключи сохраняют экземпляр fallback; равные пропсы позволяют пропустить его рендер. Локальное состояние и context работают как обычно в React.

Публичные пропсы должны удовлетворять обязательным входам всех возможных веток. Source выбирает только ключ: он не передаёт суженный discriminated payload в пропсы ветки. Если ветке нужны state/actions, сначала подключите её через holo.

## Почему такой API

Это переиспользуемая декларация выбора View по состоянию с явной полнотой cases. Для одной локальной ветки обычный switch или условный JSX может быть понятнее. Ion позволяет получить компактный ключ статуса без отдельного планировщика match.
